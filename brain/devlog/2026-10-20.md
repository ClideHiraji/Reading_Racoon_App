## Done (evening): first backend slice
- Started the Laravel backend in `backend/` ([[D-001 Backend Laravel + PostgreSQL]]): Laravel 12 (XAMPP's PHP 8.2 rules out Laravel 13), Sanctum, `.env.example` on PostgreSQL. Setup steps and the API contract are in `backend/README.md`.
- Schema for the data the game already produces: `users` (role), `sections`, `students`, `bkt_states` (14 per student), `path_progress`, `student_wallets`, `intervention_flags`, `sync_events`. All times `timestamptz`. Progress noted under issue 8 in [[10-open-issues]].
- Endpoints:
  - `POST /api/auth/login`: temporary student login by an 8-character code, stored only as a hash (interim for issue 9).
  - `GET /api/config`: BKT parameters (Table 3.5), level ranges, mastery 0.95 / 5 attempts, hint 0.30, content version, server time.
  - `POST /api/sync`: idempotent by event UUID, each event checked on its own, replies with acknowledged and rejected ids ([[D-008 Offline sync contract]]).
- Tests: PHPUnit for login, enrolment, config and sync (same batch twice = no duplicates). **All 34 pass on PostgreSQL 18.6** (883 assertions). Running them on a real database caught one bug: an API request with no token and no `Accept: application/json` header got a 500 instead of a 401 ([[Laravel API guests need a null redirect]]).
- Local setup: PostgreSQL 18.6 via winget, `pdo_pgsql` enabled in XAMPP's `php.ini` (backup `php.ini.bak-2026-10-20`). A reinstall reused the old data folder with an unknown `postgres` password; reset through `pg_hba.conf` ([[Reset a lost postgres password]]). The `reading_racoon` role and both databases exist; its generated password is only in `backend/.env`. Migrations ran on `reading_racoon`. `pg_hba.conf` is back on `scram-sha-256` (all six rules), and the 34 tests still pass with password checks on.
