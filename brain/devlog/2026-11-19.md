## Done: the backend hardened for internet access from the home laptop (D-036)
- The user asked for a fault-tolerant, lossless, secure client–server path with the server on the home laptop and students at school. The request was rewritten as an engineering brief: [[Backend hardening brief]].
- **Merged the backend first** (worktree `backend-stability-remote-fb7235`): the dashboard and admin portal (PR #2 with its unpushed Library commit), the Gemini report, the Closet event types, and Boost with today's security updates. `composer.lock` rebuilt; `composer audit` clean; 153 tests passed before any change. The dashboard's open issues 22 and 23 are now 38 and 39 (the game branch uses up to 36).
- **Audit findings, all fixed:** no trusted proxy (behind a tunnel every school shared one rate-limit bucket and the admin allowlist couldn't work); the sync acknowledgement waited on the full BKT replay (43 µs per stored event, so a failing or slow replay could make a device retry forever and an outage's backlog a retry storm); login codes as unsalted SHA-256 (31^8 codes, reversible from a leaked backup); tokens that never expire; no security headers, CDN script without SRI, CORS open; no database timeouts; no backups, log retention or health check; the game's queue rewritten in place (a crash could empty it), no jitter, no https rule, downloads restarting from zero.
- **Built:** trusted proxies, CSP/HSTS headers, SRI, closed CORS; `ReplayStudent` job (debounced, inline when the worker is down); HMAC login codes with upgrade on sign-in; token expiry and prefix; DB timeouts; `app:backup` (verified dump, off-site copy, restore drill passed), retention and pruning on a schedule; `/api/health`; `app:preflight`; `.env.production.example`; the game's atomic queue, jittered backoff with Retry-After, https-only release builds, resumable 4 MB chunk downloads; Apache include, Windows startup tasks with a supervisor, Cloudflare Tunnel config; runbook `docs/deploy/home-server.md`.
- **Measured and verified:** load test through Apache (30 learners × 5 backlogged batches at once, then a retry storm): 300 requests, 0 errors, every event stored exactly once; median 2.3 s, a 100-event sync about 120 ms after fixing three bottlenecks (validator per event 1.3 → 0.02 ms, OPcache off, `.env` per request). End to end with the game: upload, a server outage with the queue kept and delivered, a 9 MB video resumed from 5 MB.
- A self-review (code-review skill, high) found 8 more issues (health 500 when the DB is down, downloads stalling behind a Range-ignoring proxy, CR lines dropped, a misleading preflight check, stale state with no worker, sleeps on the main thread, backups ignoring `DB_URL`, buffered worker logs); all fixed with tests.
- Tests: backend 172 pass; game 5,150 checks, `ui_smoke` OK, no warnings; `sync_e2e.gd` new.
- The insecure-defaults plugin's pipeline needs a `Workflow` tool this session didn't have; its six checks were done by hand.
